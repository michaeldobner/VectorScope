# Own server

[Deutsche Version](../de/server.md) · [Overview](README.md)

Since collection 0.11.0 VectorScope can run on an own server, deployed by [Coolify](https://coolify.io): app, proxy, collector, database and raw archive at one address. GitHub Pages, the proxy on Vercel and the collector on GitHub Actions keep running as before, so nothing breaks while the server is being set up.

## What runs

`docker-compose.yaml` in the repository root defines four services. Web and collector use one image (`server/Dockerfile`).

| Service | Job | Healthcheck |
|---|---|---|
| `vectorscope-web` | Serves the built app (start page, AIR, INTEL) like GitHub Pages, the proxy under `/proxy`, the collector data under `/data/latest.json` and a small API. Port 8080 inside the stack (`server/web.mjs`) | `/healthz` answers |
| `vectorscope-collector` | One collector round every 10 minutes (`server/collector-loop.mjs` runs `collector/collect.ts`). Writes the files, the raw archive and the database, pushes the raw archive to GitHub | Last good round younger than 30 minutes (`server/collector-health.mjs`) |
| `vectorscope-db` | PostgreSQL 16, reachable only inside the stack | `pg_isready` |
| `vectorscope-backup` | Once a day a dump of the database to `/var/backups/vectorscope` on the host, keeps 7 days. Also copies new files of the raw archive to `/var/backups/vectorscope/raw` | none |

A container whose healthcheck fails shows on the status page and raises the Telegram alarm there.

### Addresses

| Address | Contents |
|---|---|
| `https://vectorscope.duckdns.org/` | Start page, `/air/`, `/intel/` |
| `/proxy/...` | Same routes as the proxy on Vercel (adsb.lol, feeds, Telegram, translation, photos) |
| `/data/latest.json` | Reports of the last 72 hours, read by INTEL on this address |
| `/api/health` | State for the status page, see below |
| `/api/reports?hours=24&source=baza&q=Tuapse&limit=200` | Reports from the database |
| `/api/diag` | Whether the server reaches the publishers: DNS and one request per host with time. First stop when the app keeps loading |
| `/healthz` | Liveness for Docker |

The app recognises where it runs: on GitHub Pages (`*.github.io`) and locally it uses the proxy on Vercel and the collector data on GitHub, on every other address its own `/proxy` and `/data`. One build serves both.

### `/api/health`

```json
{
  "ok": true,
  "version": "0.11.0",
  "collector": { "last_round": "2026-10-08T21:10:00.000Z", "age_min": 3.2, "ok_sources": 74, "sources": 75, "items": 1480, "exit": 0, "raw_push": "pushed", "reports_24h": 1650 },
  "db": { "ok": true, "reports_24h": 1650, "reports": 5200, "rounds": 140 }
}
```

`ok` is true when the collector wrote a round and the database answers. `raw_push` is `off` (no `RAW_PUSH_URL`), `pushed`, `nothing to push`, `failed` or `branch not reachable`.

## Data

| Where | What | Backup |
|---|---|---|
| Volume `vectorscope-data`, folder `/data` | `latest.json`, `archive.json`, `stats.json`, `health.json`, `raw-state.json`, `heartbeat.json` | Rebuilt by the collector |
| `/data/raw` | The raw archive with every file. Not public: the full texts of the publishers | `/var/backups/vectorscope/raw` daily. With `RAW_PUSH_URL` also pushed after every round, then only to a **private** repository |
| Volume `vectorscope-pg` | Database: table `reports` (one row per report, earliest time and first sight), `rounds` and `meta`. On its first start the collector fills it once from the raw archive (`collector/backfill.ts`), so it holds the history since 30 September 2026 | Daily dump to `/var/backups/vectorscope` |

The raw archive is the source of truth ([Raw data](../../intel/docs/en/raw-data.md)). The database is derived from the collector and can be rebuilt. Round files of the server are named `HHMM-srv.jsonl.gz`, those of GitHub Actions `HHMM.jsonl.gz`, so both can write into the same branch without collisions. If one of them finds the branch moved on, it puts its own commits on top and pushes again.

## Setting up in Coolify

Steps as of Coolify 4. Names of menus can differ slightly between versions.

1. **GitHub token for the raw archive** (optional, recommended). On GitHub: Settings > Developer settings > Fine-grained personal access tokens > Generate new token. Repository access: only `michaeldobner/VectorScope`. Permissions: Contents, read and write. Expiry: until after the probe, e.g. 1 March 2027. Copy the token, it is shown once.
2. **New resource.** In the Coolify project: New resource > Public repository, `https://github.com/michaeldobner/VectorScope`, branch `main`. Build pack: Docker Compose, file `/docker-compose.yaml`.
3. **Domain.** At the service `vectorscope-web`: domain `https://vectorscope.duckdns.org:8080`. The port tells Coolify that the container listens on 8080, the address itself stays without port. The other services get no domain.
4. **Environment variables.** `SERVICE_PASSWORD_POSTGRES` is generated by Coolify. `RAW_PUSH_URL` only if the raw archive should also go to GitHub, and then only into a **private** repository: `https://x-access-token:<token>@github.com/<owner>/<private repository>.git`. Without it the archive stays on the server and in its daily backup (since collection 0.18.0, the repository VectorScope is public). Optional: `ALLOWED_ORIGIN` if the address differs, `CONTACT` for the User-Agent, `EMBED=0` to turn off the topics by meaning (on by default, the model of about 120 MB is downloaded once into `/data/models`).
5. **Deploy.** The build takes a few minutes (type check and build of all modules). Then open `https://vectorscope.duckdns.org/api/health`.
6. **First round.** On its first start the collector takes over `archive.json`, `stats.json` and `raw-state.json` of the GitHub collector, so no report counts as new twice, and checks out the branch `collector-raw`. After 10 to 15 minutes `collector.age_min` is small and `raw_push` says `pushed`.

## Switching over from GitHub

1. **Run both for one or two weeks.** Compare in `/api/health` and `stats.json` of both: sources ok, new reports per day, gaps. Both write into `collector-raw`. A post that both see is in the archive twice, `collector/parse.ts` counts it once.
2. **Switch off GitHub Actions.** Set `PROBE_UNTIL` in `.github/workflows/collector.yml` to a past date, or disable the workflow under Actions > Collector. From then on only the server collects.
3. **Point GitHub Pages at the server (optional).** `COLLECTOR_URL` in `intel/src/data/feed.ts` and the proxy addresses can point at the server, so the app on GitHub Pages profits as well. The proxy on Vercel can then be removed.
4. **Shorter interval (optional).** `EVERY_MIN` in `docker-compose.yaml`, e.g. 2. Whether Telegram accepts this rate for its web preview from a data centre is not tested yet, watch `health.json` the first days.

## Operations

| Task | How |
|---|---|
| Logs | Coolify > resource > Logs, per service. The collector prints one summary per round and `WARN` lines from the checks |
| Restart | Coolify > Restart. The collector continues with its files, nothing is lost |
| Update | Push to `main`, Coolify deploys (automatically if the webhook is on) |
| Rebuild the database from the raw archive | Empty the tables or run `npx tsx collector/backfill.ts /data/raw --force` in the collector container (Coolify > Terminal). Safe to repeat |
| Restore the database | `gunzip -c /var/backups/vectorscope/vectorscope-<date>.sql.gz \| docker exec -i <db container> psql -U vectorscope vectorscope` |
| Restore the raw archive | Copy `/var/backups/vectorscope/raw`, or clone the private repository of `RAW_PUSH_URL` |
| Query | `/api/reports`, or `docker exec -it <db container> psql -U vectorscope vectorscope` |
